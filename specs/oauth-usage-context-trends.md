### OAuth概览与API概览对齐（2026-10-11 后续）

- 用户明确要求OAuth页具备累计Token、单日Token峰值、最长聊天时长、当前/最长连续天数、Token活动、时间范围及模型用量，并保留OAuth独有的供应商、账号、模型统计与额度。外层仅有API/OAuth两个页签；不恢复套餐统计。用户自行构建，本轮不执行任何应用/Agent/固定worker构建。
- 累计查询增加`range=all`，读取CLI UsageStore当前实际保留的OAuth记录，受供应商/账号/模型筛选影响，但不受下方24h/7d/30d选择或分页影响。范围查询和累计查询各自沿原服务与V4命令读取，旧响应仍按请求键/Host隔离。保留现有30天账本清理策略；不得把已清理记录或授权前历史补成零，也不得将其称为永久全历史。
- 累计已知Token和单日峰值只使用usageKnown的输入+输出；完全未知显示“未知”，真实零可显示0。连续天数按调用端IANA时区的已知Token>0自然日计算，与API页口径一致；当前连续从今天算起，今天尚未有已知Token时为0。活动图保留无用量上报的请求标识，不能把未知解释为零消耗。
- 最长聊天时长沿API已有口径：同一会话内与筛选后的OAuth请求关联的已完成turn.durationMs求和后取最大；每轮在同一统计集合只计一次，不把会话中轮次之间的空闲墙钟时间或模型请求耗时额外相加。混合轮次完整时长可分别参与API/OAuth页统计，两个页签的会话时长不可直接相加。无可用轮次时长时为未知。

- Shared ProviderUsageSnapshot可选新增activity及dailyModels；旧Agent快照仍可显示原摘要/表格，缺失新指标为不可用，不伪造零。所有查询筛选与归属仍由已结算账本决定，不读取当前登录来倒推历史。不增加DB迁移、凭据快照或第二统计账本。

- 验收覆盖：累计和范围独立、真实SQLite累计/峰值/关联轮次/DST/连续与断档、同名模型、未知/真实零/空态、删账号后历史筛选不丢、迟到响应、桌面/手机及中英文活动模式和模型图。根目录与CLI类型检查/Lint及架构必须执行；构建由用户执行。

## 数据所有权与接口

| 事实                 | 唯一 owner                               | 读取/投影                                           |
| -------------------- | ---------------------------------------- | --------------------------------------------------- |
| 实际 OAuth 连接      | Host 账号池执行边界                      | 每次响应传递安全 connectionId，CLI 捕获             |
| 请求用量与账号归属   | CLI UsageStore `model_usage`             | 新只读统计 query → Host UsageStatsService → UI hook |
| OAuth 当前配额       | ProviderAccounts 调用该连接 driver.quota | 白名单归一化 DTO，不发送私有 grant 或原始响应       |
| 会话上下文样本       | CLI 会话事件/持久化事实                  | 同一会话投影或严格会话查询 → 上下文面板             |
| 时间/供应商/账号筛选 | UI 局部状态                              | 不写入凭据或模型配置                                |

所有共享 DTO 提供严格运行时 schema。Host 只转发和解析账号配额；Main 不增加统计业务状态。UI 使用 `packages/ui/src/hooks/` 和现有服务 accessor，不访问数据库。现有 UsageStore 是唯一调用账本，不另建 Host HTTP 请求计数作为第二账本。

请求归属新增 nullable/optional 字段，旧数据库以 additive migration 升级，不猜测旧 connectionId。每条结算沿用已有幂等主键；账号池失败切换以实际返回该响应的账号归属，SDK 重试只接纳对应请求的最终结果。未返回有效账号头的失败保持未知；上游原始错误正文、Cookie、授权头和 token 不进入统计 DTO。网络尝试与逻辑请求的数量不得混为一谈，未观测到的失败尝试用量不虚构。

```text
会话模型请求 → Host 账号池 → 实际账号响应（安全 connectionId）
  → CLI 请求结果/事件 → UsageStore 幂等写入
  → usage 只读查询（范围 + provider + connection）→ Host → UI 概览

账号额度刷新 → ProviderAccounts（连接锁 + 当前凭据代次）
  → driver.quota → 安全、标准化额度 DTO → UI 当前额度区

本会话模型完成 / 明确压缩事件 → CLI 上下文样本事实 → 持久化/投影
  → desktop-continuous 实时状态 ─────┐
  → web-remote-replayable 快照恢复 ──┴→ 同一会话上下文走势图
```

服务请求继承当前 Environment；workspaceIdentity 用于身份、workspacePath 用于读取，远端保留 remoteSessionId/owner lease。桌面本机设置沿用 LocalHost 范围，不汇总不相关远端环境的数据库；手机会话复用原 Host attachment。快切范围/会话、晚到响应、重连和重复事件不能串账号、跨会话或重复记账。

## 验收场景

1. 同供应商 A/B 两账号，A 限流切 B：成功请求及 Token 只归 B；未知失败不归给 A 或当前活动账号；多会话并发独立。
2. 两供应商同名模型、停用/删除账号、旧无归属记录：筛选、分组及历史身份正确；原 API 统计不变化。
3. 已知 100 输入（60 cache read）、20 输出（5 reasoning）总量为 120；未知请求不补造 Token。重复结算不重复累计。
4. 统计范围边界、按调用端时区归桶、空日期、无工作区/存储不可用、SQL 过滤绑定参数、查询数量有界；筛选异步响应乱序不覆盖新页面。
5. 各类 quota 标准化、unsupported/error/空额度、账号删除/启停/刷新竞态；返回 DTO 中无原始私有数据。
6. 同会话水位增长、真实压缩后下降、模型容量改变、容量未知、重连/冷恢复与样本截断；重复事件/旧轮次/另一会话事件不产生重复或串线。
7. 桌面与手机、中英文、深浅主题、键盘操作、图表可读标签/空态；新增交互通过浏览器 E2E。

实施顺序：先规格与数据契约，再请求归属/持久化/查询及测试，再配额与 UI，最后执行全仓及 CLI 类型/Lint、架构和相关 E2E。自动化 fixtures 与真实厂商账号验证分别报告。

## 实现边界

- 统计通过 `v4/usage/providers` 读取当前本地 Host 的已有 Agent 客户端。尚未打开工作区、没有可用客户端时显示不可用并提示打开工作区；此时账号额度仍可独立读取。查询只读 `model_usage` 的已结算 OAuth 请求，保留原应用用量查询。
- 时间范围按当前时刻回溯，并使用调用端 IANA 时区归入自然日（近 24 小时可以跨两个自然日）。最近请求每页 25 条，协议最多 100 条。筛选响应按服务实例和请求参数隔离，旧响应不能覆盖新筛选。
- `0025-oauth-usage` 只新增归属、已知用量和请求上下文字段。旧正数用量保留，旧零值无法判定是否上报时标为未知。历史 OAuth 渠道可由既有 provider ID 识别，账号不能补猜。
- `ProviderAccounts` 独占额度缓存与在途请求，缓存 60 秒，单次读取最多 30 秒；账号状态/凭据代次变化后丢弃旧结果。刷新失败可显示同代账号上次成功的额度并标记过期；纯余额/信息项不推导成百分比。
- `usage.contextTrend` 是 V4 快照的可选安全字段。以 assistant message 与明确压缩 operation 的稳定 ID 去重，最多保留最近 200 点并标明截断；冷恢复读取已有消息和压缩边界。历史请求容量来自当时保存的 metadata，缺失时为未知；明确 rewind 移除被放弃分支的样本。
- 趋势入口位于会话上下文详情及只读子会话 Token 信息。图表按需加载，同时提供时间、事件、模型、水位和容量的表格。
