# 设置页控件列宽度

## 产品规则

1. 设置页每一行是「左侧标签与说明 + 右侧控件」的两列布局，桌面端右侧控件列宽度由行决定，窄屏（< md）堆叠为单列。
2. 控件列有两种宽度：`default` 为 192px，`wide` 为 280px。宽度属于行（`SettingsRow`），不属于行内的具体控件。
3. 行内控件不得再声明自己的固定宽度。控件使用 `w-full` 填满控件列；下拉框统一 `size="lg"`（32px 高）。
4. 同一张 `SettingsGroupCard` 内的下拉框必须同宽同高，右边界对齐。
5. 选择 `wide` 的判断依据是内容宽度，而不是视觉偏好：需要完整显示最长选项文本的行使用 `wide`。

## 为什么禁止控件自带宽度

`SettingsRow` 的控件列由 `grid-cols-[minmax(0,1fr)_192px]` 或 `..._280px]` 决定。控件再声明 `w-[260px]`、`w-52`、`w-64` 等固定宽度时，两者会互相覆盖：

- 控件宽度小于列宽时，下拉框在列内左对齐，右边界参差；
- 控件宽度大于列宽时，被 `minmax(0,1fr)` 与列宽截断，实际宽度不可预期。

同一页曾同时存在 192px、256px、280px 三种宽度和 28px、32px 两种高度，正是因为宽度来源被分散到两个层级。

## 宽度判定

`wide` 的 280px 列在扣除 `size="lg"` 的内边距（左 12px、右 8px）与箭头（16px）后，可用文本宽度约 238px。`default` 的 192px 列约 150px。

已核对的最长选项是提交审核的英文 "Generate and open review"，实测 163px：`default` 列放不下，必须用 `wide`。中文最长项「生成并打开审核」98px、归档「30 天后归档」75px，两者在任一列都放得下，但为保持同卡片一致仍使用 `wide`。

## 验收场景

- 1280px 下「常规」分区所有下拉框宽度与高度一致（280×32），右边界对齐。
- 390px 下同样一致（随列宽收缩，约 239×32），且无横向溢出。
- 中英文下最长选项都不被截断（`scrollWidth <= clientWidth`）。
- 切换语言、主题、界面模式后宽度不发生变化。
- 现有回归：`mobileSettingsLayout.test.tsx` 覆盖 `default`/`wide` 两种行的堆叠与控件列宽度；`worktree-review-settings-cases.mjs` 覆盖提交审核下拉框的键盘选择与不横向溢出。
