# 供应商 API Key 探测隔离

## 产品规则

1. API Key 管理对话框的草稿、忙碌状态和探测结果只属于打开它的供应商。
2. 切换供应商、关闭对话框或卸载组件时，当前操作立即失效。已经发出的请求可以结束，但其迟到结果不得更新新的对话框状态，也不得继续提交后续保存。
3. 同一供应商内，探测前保存草稿引起的配置刷新不得取消本次探测；操作代次只由新操作、供应商切换、关闭或卸载推进。
4. 探测结果中的无效 Key 只写回发起探测的供应商。供应商切换后，不再发起关闭无效 Key 的第二次保存。

## 状态所有者

- `ProviderApiKeyManagerDialog` 拥有当前供应商的 Key 草稿、探测状态、错误和忙碌状态。
- 纯操作代次守卫拥有 `scopeKey + generation`，不拥有业务数据。
- Provider Settings Service 继续拥有配置保存和远端探测；UI 不绕过现有服务接口。

## 事件顺序

```text
打开供应商 A → 建立 A 的操作代次 → 保存 A 草稿 → 探测 A
切换供应商 B → A 代次同步失效 → 重置为 B 草稿
A 的迟到结果 → 代次校验失败 → 丢弃，不更新 UI，不继续保存
B 的新操作 → 使用 B 的新代次独立执行
```

## 验收场景

- A 的探测未完成时切到 B，B 不显示 A 的状态、错误或忙碌状态。
- A 的探测在切换后返回无效 Key，不触发关闭 Key 的第二次保存。
- A 的首次草稿保存引起父组件刷新时，A 的探测仍继续并保留最终结果。
- 关闭对话框或卸载页面后，迟到结果不再更新组件状态。
