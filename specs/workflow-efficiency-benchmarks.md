# 工作流效率与持续负载验收

## 范围

用户要求完成工作流优化剩余的 CLI 质量清理、真实模型对照和持续压力测试。质量规则沿用 `lint-clean-baseline.md`；本文件固定评测口径，不改变生产调度、模型默认值、重试策略或协议所有权。结果必须由实际运行生成，失败、取消、环境限制与完整成功样本分开统计。

## 真实模型配对对照

- 仅向用户现有供应商发送明确的合成任务、合成规范和合成输入；不发送当前仓库源码、Git diff、真实会话、文件路径、凭据或内部地址。凭据通过现有 provider 配置和 adapter 在内存中使用，不复制进脚本、报告、日志或临时数据集。
- 请求模型固定为用户当前配置的 `new-provider-2/gpt-6-astra`，显式保留 `reasoningLevel=max`、`speed=fast`。执行前核对 adapter 的实际配置；不因辅助 generateText 的默认档位或 provider 错误静默降档/切模。
- 最少五对样本，旧/新安排交错（AB、BA、AB、BA、AB）。每对的任务内容、输入、允许工具、输出验收和模型选项完全相同，两个安排从空白、独立的任务上下文开始，不复用另一安排的回答或调用 `ReadSessionContext`。
- 旧安排在首个领域调查交付后才启动另一个独立领域调查；新安排尽早发出两个领域调查，公共契约及集成仍等待其真实依赖。不得把少请求、少任务或取消最终验收产生的耗时差称为优化收益。
- 每个交付有预先固定的机器验收；首次有效交付时间只计被验收接受的任务结果，不计流式文字、日志或文件编辑。最后结果未通过验收时，整次运行记失败，不纳入成功配对的加速统计。
- 记录每次物理请求、逻辑任务、排队/准入、退避、模型处理、工具执行、准确已结算用量、首个有效交付和全部验收完成时间。并行耗时不简单求和作为墙钟耗时。请求未提供某类指标时显示缺失，不能编造 0。
- 输出逐对原始数字及中位数、范围、异常解释；五对是探索性样本，不报告稳定 p95、显著性或生产任务加速保证。合成场景结论不等同完整 Git 发布任务，也不自动证明模型在任意复杂任务中遵守拆分指导。
- 评测有明确运行时限与请求输出上限；超出只中止本次评测的请求并保留失败结果，绝不操作用户正在运行的任务。原始错误只保留归一化类别，不输出供应商可能包含敏感内容的错误正文。

## 多代理持续压力

### 唯一所有者与链路

```text
合成请求/流/工具事件 → 每 actor 独立 runtime 事件流
    → 生产 workflow driver（每 ask 节流与代次边界）
    → Engine/journal → ProductProjection/shared reducer
    → continuous 在线 / replayable 恢复 → 真实 React 组件

采样器只观察计数、时间和资源，不成为队列、snapshot 或 usage 的第二写入者。
```

- 档位为 12、64、256 个 actor，每个 actor 独立 session/query/turn；每秒每 actor 20 个同类可见 delta，穿插有界的请求、工具、退避和结算边界。生产 observer/engine/reducer 不能换成空函数以获取更好结果。
- 每档先预热，再持续至少 60 秒；至少另做一档多 actor 的 5 分钟持续运行。真实墙钟负载和加速虚拟时间用例分开记录，不能把虚拟 5 分钟称为持续资源实测。重复次数、预热长度和构建模式与结果同时发布。
- 节点累计超过 256 时验证投影窗口有界、活动节点保留、截断可见；触发同订阅恢复与陈旧事件，恢复后事实与在线结果一致，源时间不被重置。
- 分层记录输入 delta 数、activity 事件数、生命周期事件数、投影更新、传输字节/帧数；普通 1Hz 合并与必须即时发出的状态变化分别统计。
- Node 资源指标使用 `process.cpuUsage()` 差值除墙钟（单核 100%）、RSS/heap 起点/峰值/结束及稳态趋势。只保留有界计数与采样数组，避免基准自己的无界事件缓存制造泄漏。
- 浏览器必须真实渲染共享工作流组件，采集 React commit 时长/次数和 RAF 帧间隔、长帧比例；不能以 SSR 耗时冒充界面渲染。同步恢复、窄屏和详情交互在负载中仍可操作，记录错误及停止后订阅/timer 收尾。
- 不预设性能通过结论。功能不变量失败、资源超过事先声明的安全预算或测试无法清理时，本档失败且保留结果；性能数字按本机、当前构建和输入规模报告，不宣传为跨机器 SLO。
- 恢复一致性比较以协议 schema 规范化后的事实为准，不把 JSON 对象键的插入次序当作产品状态差异；字段值、缺失与数组顺序仍必须匹配，陈旧帧不能覆盖现有事实。基准自身的误报也保留原始样本，修正比较后另记复测，不覆盖失败记录。
- 测量时钟在停止时冻结，停止后的查询不延长测量窗口；RAF 间隔覆盖的时长与总墙钟分别报告。后台调度、长任务或测试控制造成的真实空档不扣除、不用虚拟帧补齐。

## 产物与复现

评测脚本、合成数据生成器、结果校验和测试归入 benchmark/test 边界；生产模块只因真实缺陷修复而改变，先补回归。结果文件只包含匿名任务编号、模型公开 id/选项、用量、时间、资源和验收状态，不包含 prompt、输出全文、内部地址、密钥或用户路径。真实评测必须显式开启，不纳入普通单元测试，也不自动访问供应商。

安装包、用户插件缓存和线上服务不在本次范围；不能因评测需要更新或停止现有应用。

## 实测结果（2026-10-02）

- 五对真实模型全部完成，10/10 arms、30/30 任务精确验收通过；配对总加速中位数 1.701×，范围 1.265–2.285×。第 2 对新编排的首次交付略慢也原样保留，不重跑挑选样本。
- 持续运行时 12/64 actor 的 60 秒与 64 actor 的 5 分钟档位完成；256 档修正基准后仍因固定墙钟预算失败，实际 6.556 delta/s/actor。初始缺测与修正失败分别保留，未提升预算或改变生产策略。
- 浏览器开发构建完成 12/64/256 桌面及 64 actor、390px replayable 测量。恢复与 stale 不变性、真实详情操作、256 节点窗口与收尾通过；256 档实际 16.208 delta/s/actor，RAF 间隔 >50ms 占 74.38%，不声明性能达标。
- 原浏览器恢复一次误报来自 JSON 键插入次序差异，经实际 Controller + Store 复现并补 9 个基准回归；原样本未删，规范化后另记复测。RAF 首尾覆盖单独报告，停后时钟冻结。
- 完整数字、构建与测量边界、原始 JSON、复现方式见 `docs/benchmarks/workflow-efficiency-2026-10-02.md`。所有本测试 timer/listener/subscription 收尾完成，临时页面和服务器已关闭。
