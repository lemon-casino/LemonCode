# 模型供应商设置

## 产品规则

1. 模型设置只管理个人 API 供应商。`BigModel`、`Start Plan`、套餐卡、登录、连接方式和账号解绑入口不在模型设置中出现；账号登录能力是否存在、是否曾连接都不能改变这条规则。
2. 添加供应商时，智谱模板仍单独成组。其余模板按品牌分类：Kimi、MiniMax、DeepSeek、阿里云、小米、OpenAI、Anthropic、xAI、OpenRouter、OpenCode。无法识别的模板才进入“其他”，自定义供应商也在“其他”。
3. 选中个人供应商后，“同步模型”和“添加模型”是两个相邻但独立的按钮，不能共享弹框或点击事件。“同步模型”打开独立对话框并立即从供应商 `/models` 接口拉取目录；“添加模型”仍打开单模型编辑器。
4. 同步对话框仅保留一个提交动作“检测并添加”。默认勾选远端目录与已配置模型的去重并集；选择部分时只检测这部分，全选时检测全部。按钮显示本次范围和数量；取消全选后按钮禁用，空选不能暗中解释成全部。全选/取消全选均只修改勾选草稿。搜索时提交范围按“搜索与失效模型清理”一节收缩。
5. 检测使用现有正式 Model 执行链，最多同时检测 4 个模型；不能在检测前逐个写入配置，也不能在 stdio 协议层把这些独立检测重新串行化。每项独立返回结果，某个模型失败不得中断其他项。显示完成数、每项成功/失败和失败原因。
6. 尚未配置的模型只在检测成功后使用推荐配置添加；失败项不进入模型列表。已有模型成功后启用，保留既有名称身份、配置模式、参数和顺序；失败项保留但关闭。禁用模型也可进行真实检测，不得因其禁用状态直接报不可用。
7. 同一供应商内模型身份是去除首尾空白后的原始 Model ID。目录、配置成员和顺序均去重；重复添加同一 ID 幂等，不产生第二行、不覆盖已有参数。不同供应商的同名模型、大小写不同的真实 API ID 和不同版本/别名不合并，不能为去重改写实际请求的 ID。
8. 模型列表中每项均可删除，包括模板继承的内置模型。删除立即从设置和可选模型投影移除；个人配置保存 `excludedModelIds` 排除记录，刷新、重启和模板刷新不得自动恢复。手动添加或检测成功后显式添加同一 ID 可解除排除。删除不是禁用，不能用 `enabled=false` 假装删除。
9. 一个个人供应商可保存多个 API Key。模型设置提供统一“管理 API Key”入口，支持新增、批量导入、分页、删除、删除全部、删除无效 Key、启停和并发检测。批量导入支持粘贴、剪贴板、拖拽文件及选择文件，后台自动识别分隔文本与 JSON，去重后追加草稿，支持十万条以上；规则见 [批量导入规范](./provider-api-key-bulk-import.md)。检测使用供应商模型目录接口，明确的 401/403 判为无效并自动关闭该 Key；网络错误保留启用状态并显示失败原因。
10. 请求在启用的 Key 之间按顺序轮询。一次请求收到明确的 401/403 时，在同一次请求内使用下一个启用 Key 重试；其他 HTTP 错误或网络错误不在同一次请求内切换。进程内记住已鉴权失败的 Key，后续请求跳过它；重新保存配置后重新建立运行时状态。
11. 旧配置只有 `apiKey` 时，读取为一个兼容 Key；保存 Key 列表时同时写入第一个启用 Key 到 `apiKey`，保证旧运行时和迁移工具可继续读取。

## 搜索与失效模型清理

- 同步对话框提供即时模型 ID 搜索，去除查询首尾空白、忽略大小写作包含匹配，不改写原始 ID。搜索只过滤显示，不丢失已勾选项和已完成的检测结果；清空搜索恢复完整目录。无匹配时显示明确空态。
- 有查询时“全选模型”变为“选择搜索结果”，点击后以全部匹配项替换当前选择。显示匹配数与全局已选数；搜索时提交按钮变为“检测并添加指定模型（N）”，提交范围收缩为匹配项与勾选的交集（默认勾选下即全部匹配项），数量为本次将处理的匹配数，避免默认全选的隐藏模型被误检测；无查询时仍处理全局选择快照，按钮范围/数量准确。筛选本身不发网络请求。
- 模型列表标题右侧顺序为“删除失效模型 / 同步模型 / 添加模型”，窄屏允许自然换行，不隐藏主操作。
- “删除失效模型”一键打开并开始检测当前已配置模型快照，最多 4 路并发，包含已禁用和继承模型；使用临时检测，不预先改变任何启用状态。仅目标模型被供应商明确拒绝且以结构化错误码确认为不存在/不支持时，才沿现有模型删除命令移除。成功、超时、连接故障、429、5xx、账号/API Key 401/403、供应商或本地配置不可用均保留；不能把 disabled=false、简单 HTTP 404 或错误消息文字当删除依据。
- 清理对话框显示检测进度，以及每项“可用，保留 / 失效，已删除 / 无法确认，保留 / 删除失败”的结果和原因。无模型时清理入口禁用。未找到明确失效项时清晰显示未删除，不以全部请求失败宣称清理成功。
- 清理与同步/添加互斥；同批写入仍静默使用 Provider mutation 队列，不产生逐项保存提示。关闭、卸载或切换供应商停止后续调度；迟到结果不得删除模型，已接受的删除事务可完成。单项检测或删除失败不阻断其余模型。
- `ModelConnectivityResult.error.code` 和连通性协议失败结果新增 `model-not-found`，仅由目标 Environment 的模型执行错误结构化分类产生。未知异常仍是失败但不可自动删除；旧成功结果及不携带该码的错误继续兼容。不得将响应全文或凭据作为错误分类字段跨边界传递。

```text
搜索词 → UI 过滤显示 → “检测并添加指定模型”仅提交匹配项与勾选交集
删除失效模型 → 已配置 ID 快照 → 最多 4 路临时检测
                              ├─ 结构化确认模型失效 → 现有删除命令 → 个人排除记录/Registry
                              └─ 有效或无法确认 → 保留配置，仅展示结果
```

## 所有者与接口

- Provider 配置 Repository 是模型成员、`excludedModelIds`、模型启用状态和 Key 列表的唯一持久化所有者。沿用 Provider Settings Facade 的每供应商 mutation 队列与 revision 校验；UI 不保存第二份权威成员名单。
- Provider Settings Service 拥有远端目录读取和 Key 检测；UI 通过 `useModelProviders` 调用服务，不直接发送供应商网络请求。
- `testModelConnectivity` 和 `provider/testModelConnectivity` 增加可选 `mode: "temporary"`。缺省仍只接受已发布的正式模型；临时模式由目标 Environment 根据权威 Provider 配置及同一套模型推荐/个人规则解析一次性 Model，允许未加入列表和已禁用的模型，不写配置、不修改全局 Registry、会话选中项或模板源。供应商禁用、配置不完整、鉴权不可用仍失败，不能绕过资格校验。协议继续使用严格 schema。
- 临时 Model 复用正式 Adapter、API Key 轮询、自定义 headers、最低 reasoning/speed 档位与固定最小探测请求；不新增简化 HTTP 成功判定。连通性成功只证明最小生成请求完成，不宣称工具调用等所有能力均已验证。
- 单项检测、同步模型及失效模型清理共用的连通性入口，按正式执行链使用目标模型 `optionSpecs.maxOutputTokens.max` 作为请求输出预算，不强加固定的 1 Token 或其他探测专用 Token 数。保留最低 reasoning/speed 档位、最小探测提示、60 秒 deadline 和调用方取消；预算是上限，不要求模型输出到该长度。供应商的参数校验失败不能据此判定 API Key 错误或模型不存在。
- `gpt-6.1-sol` 的智能配置声明 `low / medium / high / xhigh / max`，不继承通用的 `disabled`、`none` 或缺失的 `max`。兼容带命名空间和既有分隔符后缀的模型 ID，不将规则扩散到其他未确认的型号；仅修正已知 reasoning 能力，不推断上下文、工具或输出容量。检测仍按声明顺序选择最低项 `low`，正式执行、单项检测和批量检测读取同一个权威规则；保留个人手动配置优先级，不静默改写用户配置。
- 请求运行时只读取配置列表，并仅维护进程内鉴权失败游标；该游标不是持久化配置事实。个人配置每次成功保存后，Repository 在共享运行 sidecar 中只更新该供应商的保存代次，Registry 将代次传播到新建 Model。相同保存代次继续跳过已鉴权失败的 Key；只有该供应商重新保存后才建立新的运行时状态。保存其他供应商、修改其他模型或账号刷新不得清掉当前供应商的失败游标。
- UI 只拥有勾选、检测进度、结果和操作代次。Settings 继续使用现有 Local Host 作用域，不因为切换到远程工作区而将请求发送到另一套 Provider 配置。

## 事件顺序与取消

```text
同步模型 → Provider Settings Service 拉取目录 → UI 去重并默认全选（不写配置）
        → 用户提交选中 ID 快照 → 最多 4 路临时正式 Model 检测
                                  ├─ 成功 → 现有 Provider 写队列添加/启用 → Repository → Registry → UI
                                  └─ 失败 → 未配置项不保存；已有项经同一写队列禁用 → UI 失败原因

删除模型 → Provider 写队列 → 移除个人成员/精确规则 + 保存排除 ID → Registry/Settings 投影移除
显式添加 → Provider 写队列 → 解除对应排除 + 幂等成员添加 → Registry/Settings 投影恢复

管理 Key → UI 草稿 → 保存 Provider access.apiKeys → Registry 刷新
       → 模型请求使用第一个启用 Key → 401/403 → 同请求切换下一 Key
```

- stdio 连通性请求等待其前面的普通配置请求完成后才进入 handler，但不同连通性请求不互相等待结束；普通请求的现有顺序、取消/停止旁路和反向响应机制不变。模型创建时冻结配置，不能为并发临时替换共享 Registry 或 Factory。
- 对话框关闭、卸载或供应商切换时立即废弃操作代次并停止后续调度。已经发出的请求允许按底层协议自行结束，但迟到结果不得追加模型、启停模型或更新关闭/新供应商的对话框。关闭前已提交的配置事务正常完成，不回滚用户已接受的结果。
- 对话框打开时及用户手动刷新时才读取目录；配置更新引起的父组件重渲染、列表滚动不得重新读取目录、重置勾选或覆盖已完成的检测状态。
- 批量操作取点击时的提交范围快照：无查询时是勾选集，有查询时是匹配项与勾选交集；未选中的远端项和本地项均不得被写入或检测。运行期间禁用勾选和刷新，但始终允许关闭。
- 批量写入只在对话框内显示统一进度，不生成逐模型的全宽“正在保存”反馈层。写入失败与检测失败均可见，不将“检测成功但保存失败”显示成已添加。
- 同一供应商的配置写入继续串行化；模型和 Key 检测可并发执行。全部 Key 被关闭或鉴权失败时保留最后一次鉴权响应，不进行无限重试。

## 兼容边界

- 没有 `excludedModelIds` 的旧配置视为无排除；该字段只由个人配置层持有，普通 Provider 字段保存和排序必须保留它。模板与账号事实源不拥有用户排除记录。
- 删除不改写内置模板文件或模型推荐规则，不恢复仓库中已移除的账号 UI。保存或启停已被删除的模型不能绕过显式添加使其复活。
- Desktop 与 Web 共用组件、hook 和服务契约；手机只操作已有 Host attachment。此功能不修改会话流、快照恢复、CommandInbox、owner/lease 或 workspace identity 规则。

## 验收

| 场景 | 操作与断言 | 验证层 |
| --- | --- | --- |
| 部分与全部 | 默认全选；取消后只勾选部分并提交，只检测所选；再全选处理全部；空选禁用 | UI 交互回归、选择快照单测 |
| 有效模型入库 | 同批成功、HTTP 失败与抛异常；只有成功的新项入库，失败原因可见，其他项继续 | UI 交互回归、服务/执行链测试 |
| 并发真实执行 | 前 4 项可同时进入实际 handler，请求未结束时仍能开始其他探测；第 5 项等待空位；普通配置屏障不被越过 | 并发池及 NDJSON transport 测试 |
| 内置/个人删除 | 两种模型均可删除；重新读配置和刷新模板仍不出现；重新添加可恢复 | Provider 配置/Resolver 测试、UI 删除回归 |
| 去重与重复添加 | 目录重复、成员重复、首尾空白、继承与个人重叠只显示一行；重复添加不覆盖参数；大小写/供应商身份不合并 | Provider/目录/选择测试、UI 重复同步回归 |
| 禁用恢复 | 已禁用模型确实发起网络检测，成功启用；失败保留禁用且不产生副本 | 临时 Model 与 UI 回归 |
| 关闭与切换 | 挂起检测时关闭或卸载旧供应商；释放迟到请求后不新增、启停或继续调度 | 取消单测、UI 交互回归 |
| 配置更新 | 十个以上模型逐步成功保存；勾选、滚动及已完成状态不重置，不重拉目录，不堆保存提示 | UI 交互回归 |
| 临时检测隔离 | 未配置、已删除、已禁用模型使用同一解析/Adapter；检测前后配置、Registry 和会话选择不变 | Provider/CLI 回归 |
| 搜索快速选择 | 输入含大小写/首尾空白的 ID 片段即时筛选；搜索时提交按钮变为“检测并添加指定模型”，仅检测匹配项、数量为匹配数；清空查询恢复完整范围与数量且保持选择/结果，无额外目录请求 | 搜索单测、UI 交互回归 |
| 清理失效模型 | 当前列表含成功、禁用成功、明确 model-not-found、HTTP 403/503、未知异常；仅明确失效项删除，其他成员及 enabled 不变 | 清理单测、结构化错误测试、UI 回归 |
| 清理取消/失败 | 4路挂起时关闭/卸载，迟到结果不删除且不调度剩余；删除失败保留该模型并报告错误，其余继续 | 清理单测、UI 回归 |

仍需维持既有验收：模型设置无套餐/登录内容；供应商品牌分类正确；同步与手动添加入口独立；Key 管理并发检测；401/403 同请求轮换而 500 不轮换。
