# 模型供应商设置

## 产品规则

1. 模型设置只管理个人 API 供应商。`BigModel`、`Start Plan`、套餐卡、登录、连接方式和账号解绑入口不在模型设置中出现；账号登录能力是否存在、是否曾连接都不能改变这条规则。
2. 添加供应商时，智谱模板仍单独成组。其余模板按品牌分类：Kimi、MiniMax、DeepSeek、阿里云、小米、OpenAI、Anthropic、xAI、OpenRouter、OpenCode。无法识别的模板才进入“其他”，自定义供应商也在“其他”。
3. 选中个人供应商后，“同步模型”和“添加模型”是两个相邻但独立的按钮，不能共享弹框或点击事件。“同步模型”打开独立对话框并立即从供应商 `/models` 接口拉取目录；“添加模型”仍打开单模型编辑器。
4. 同步对话框展示远端模型、当前配置状态和启用状态，支持刷新目录、全选、添加全部、移除全部个人模型、并发检测勾选模型，以及“同步并检测”。同步会为远端缺失项创建推荐配置；检测失败的已配置模型自动关闭，不删除；内置模型不能被批量移除。批量检测最多并发 4 个模型，不能一次性启动全部请求。
5. 一个个人供应商可保存多个 API Key。模型设置提供统一“管理 API Key”入口，支持新增、删除、启停和并发检测。检测使用供应商模型目录接口，明确的 401/403 判为无效并自动关闭该 Key；网络错误保留启用状态并显示失败原因。
6. 请求在启用的 Key 之间按顺序轮询。一次请求收到明确的 401/403 时，在同一次请求内使用下一个启用 Key 重试；其他 HTTP 错误或网络错误不在同一次请求内切换。进程内记住已鉴权失败的 Key，后续请求跳过它；重新保存配置后重新建立运行时状态。
7. 旧配置只有 `apiKey` 时，读取为一个兼容 Key；保存 Key 列表时同时写入第一个启用 Key 到 `apiKey`，保证旧运行时和迁移工具可继续读取。

## 所有者

- 供应商配置文件拥有 Key 列表、用户启停状态和模型启用状态。
- Provider Settings Service 拥有远端目录读取和 Key 检测；UI 不直接发送供应商网络请求。
- 请求运行时只读取配置列表，并仅维护进程内鉴权失败游标；该游标不是持久化配置事实。
- UI 草稿在保存前不改变已接受配置。

## 事件顺序

```text
同步模型 → Provider Settings Service 拉取远端目录 → UI 选择操作
        → Provider 配置事务按队列提交 → Registry 刷新 → 最多 4 路连通性检测
        → 失败模型 set enabled=false → Registry 刷新 → UI 投影

管理 Key → UI 草稿 → 保存 Provider access.apiKeys → Registry 刷新
       → 模型请求使用第一个启用 Key → 401/403 → 同请求切换下一 Key
```

- 对话框关闭或供应商切换后，旧的目录/检测结果不得写入新供应商。
- 同步批量写入只在对话框内显示统一进度，不生成逐模型的全宽“正在保存”反馈层。
- 检测、添加或移除进行中仍允许关闭对话框；关闭后立即停止调度后续模型，已经发出的请求允许按底层协议自行结束，但其迟到结果不能更新已关闭对话框。
- 同一供应商的配置写入继续使用现有 Provider mutation 队列串行化；模型和 Key 检测可并发执行。
- 全部 Key 被关闭或鉴权失败时，保留最后一次鉴权响应，不进行无限重试。

## 验收

- 无论是否存在账号连接，打开模型设置都看不到 BigModel、Start Plan、套餐和登录内容。
- 添加 OpenAI、Kimi 等模板时不落入“其他”；未知模板才落入“其他”。
- 点击同步模型只打开同步对话框；点击添加模型只打开单模型编辑器。
- 同步对话框可拉取、添加全部、移除全部个人模型，并关闭检测失败的已勾选模型。
- 检测多个模型时最多存在 4 个进行中的检测；任一检测不返回时仍可关闭对话框，关闭后不再启动剩余模型。
- 同步十个以上模型时，设置页不会堆叠逐模型“正在保存”反馈并遮挡模型列表。
- Key 管理对话框可并发检测并关闭 401/403 的 Key。
- 两个 Key 中第一个返回 401/403 时，同一次模型请求使用第二个 Key 成功；500 不触发切换。
