## 5 不进入首版的组合

| 组合                                            | 原因及可用替代                                                       |
| ----------------------------------------------- | -------------------------------------------------------------------- |
| 跨本地与远程、跨两个 Host 同时执行              | 尚无跨 Host 多范围执行与恢复合同；分区仍可混排，单环境项目可独立使用 |
| 在普通编辑中原地改变历史主目录身份              | 会影响会话与配置隔离；使用明确的新项目流程保留历史                   |
| submodule 或非 Git 目录伪装为已隔离的工作集成员 | 当前能力不支持；普通项目会话可配置合法非 Git 目录                    |
| 复制上一聊天或合并所有工作树记忆来记住路径      | 目录清单应是确定的项目事实；保留指令、证据和记忆边界                 |
| 分区清空或删除聊天时自动删除工作树              | 导航和聊天操作不构成 Git 生命周期删除许可                            |

这些组合是明确裁剪，不能在实现中添加隐式本地 fallback、随机选择默认项目或只执行一半成员来绕过门槛。

## 6 验收交接

验收清单含 **98 项新增场景**。其中 G 为分区、P 为项目、C 为上下文、W 为工作集、R 为远程、U 为交互、M 为迁移。accepted 是产品规则，planned 保留尚未逐项签收的整组验收；实际通过的代表性测试单独登记。

当前已核实的回归文件列在验收清单第 10 节。实施不能假定存在统一单测脚本；新增方法必须同步 shared schema、服务 contract、RPC 和 UI hook，并按实际 package.json 选择验证入口。

保留的能力门槛：跨 Host、历史主目录迁移、submodule、非 Git 隔离和新旧协议双向写入，不在首版隐式实现。工作集模块已登记架构策略并提供 module、contract、contract example 和 CONTRACT.md；消费者和范围协议通过公开 port 接入原 owner。
