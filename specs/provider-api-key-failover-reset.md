# API Key 鉴权失败游标重置

## 产品规则

1. 运行时按供应商保存已经返回 401/403 的 Key，并在同一保存代次内跳过它们。
2. 重新保存某个供应商时，即使 Key ID、启停状态和密文完全不变，也必须为该供应商生成新的保存代次；新建 Model 使用新代次并重新尝试全部启用 Key。
3. 保存其他供应商不得重置当前供应商的失败 Key；每个供应商拥有独立代次。
4. 设置 Host 与 Agent 是不同进程，保存代次必须通过共享文件边界传播，不能只存在写入进程内。
5. 保存代次是运行元数据，不改变个人供应商配置的业务 revision，也不写入主配置文档。
6. 同一供应商收到 HTTP 403 额度不足响应时，当前请求立即尝试下一把已启用 Key；若没有其他可用 Key，则返回供应商原始错误。不同 Key 若属于同一额度耗尽的团队，切换不能恢复服务。
7. 新 Key 必须先在供应商配置中保存并被运行时观察到；已开始的请求不等待用户追加 Key，也不跨供应商自动切换。

## 所有者与顺序

```text
Provider 保存成功
  -> Personal Repository 在同一文件锁内更新代次 sidecar[providerId]
  -> 其他进程轮询读取完整代次映射
  -> Registry 发布相同业务 revision 下的新代次快照
  -> Model 创建时冻结本供应商代次
  -> AiSdkModelExecution 按 providerId + 代次 + Key 签名选择失败游标
  -> HTTP 403 额度响应：本次请求尝试下一 Key；全部失败则保留最后一个响应
```

## 验收

- 同一 Key 列表重新保存后，之前失败的第一个 Key 会再次被尝试。
- 不重新保存时，后续请求继续跳过已失败 Key。
- 保存供应商 B 后新建供应商 A 的 Model，仍使用 A 原来的失败游标。
- 两个 Repository 实例共享同一配置路径时，读取实例能观察写入实例生成的供应商代次。
- 首把 Key 收到额度不足的 HTTP 403、第二把 Key 可用时，本次模型请求成功；后续请求跳过失败 Key。
- 仅配置一把 Key 或所有 Key 都返回额度不足时，有限次尝试后保留供应商额度错误，不空转或自动选择其他供应商。
