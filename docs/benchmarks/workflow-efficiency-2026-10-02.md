## 2. 五对真实模型对照

### 固定条件

- 模型固定为 `new-provider-2/gpt-6-astra`，显式 `reasoningLevel=max`、`speed=fast`；本地映射为 max reasoning effort 与 priority service tier。没有独立验证供应商内部如何执行这些选项。
- 两个独立调查任务 A、B，以及必须等待二者验收的集成任务 C。旧安排顺序执行 A、B；新安排提前并行发出 A、B；任务内容、机器验收、输出上限及最终交付完全相同。
- 每个 arm 是独立进程、空白内存 journal，同一公开 WorkflowEngine / AiSdkModelAdapter 构建产物。没有复用另一组结果、工具、仓库读取、标题生成、维护调用或用户会话。
- 交错次序固定 AB、BA、AB、BA、AB。每请求输出上限 5000 tokens，每 arm 时限 10 分钟，保留生产 governor 默认值与重试策略。
- 首次有效交付是机器精确验收后 Engine 的首次成功结算，不是首 token 或首条日志。总时间从 engine 构造至最终验收与结算；配置读取、进程启动、hash 与 cleanup 不包含在内。

**10/10 arms、30/30 任务通过验收**，30 个逻辑请求对应 30 个物理请求，全部正常收尾。配对总加速中位数 **1.701×**，范围 1.265–2.285×；首次交付配对加速中位数 **1.380×**，范围 0.981–3.192×。旧/新总耗时各自的中位数分别为 **12.274 / 7.214 秒**。

**结论边界：** 这证明了指定三任务图、同条件真实模型调用中提前启动独立任务的收益，不是完整桌面会话、任意复杂任务拆分质量或未来固定加速倍数的证明。

## 3. 运行时持续压力

### 测量边界

```text
每 actor 独立合成 runtime 事件
  → 生产 workflow driver → WorkflowEngine / InMemoryJournalStore
  → ProductProjection / Publisher → wire 编码与组装 → shared reducer
      ├─ desktop-continuous 在线
      └─ web-remote-replayable 恢复
```

没有真实供应商或网络 socket。CPU 包含真实 journal 保留、投影序列化计数、Publisher 的 2000 项 delta 窗口、编码、schema 校验和采样开销；不是纯 Engine CPU。传输数字是实际编码后的字节计数，不是实网吞吐。运行时与浏览器分别测量，不能拼接成同一次端到端观测。

运行时结果对应 JSON 记录的测量构建：source driver 与当时固定的 Engine/Projection dist，后续 CLI 全量重构构建用于最终回归。源目录在测量期间存在其他重构活动；前后目录 hash 和模块缓存并不能证明全部传递模块加载字节完全一致，`loadedSourceByteHashVerified=false` 如实保留。因此这些数值不冒充最终安装产物的压力认证。

每 actor 目标 20 delta/s，每 50ms 一批，预热 10 秒；12 / 64 / 256 actor 各目标测量 60 秒，额外 64 actor 目标 300 秒。安全预算固定 RSS 1.5 GiB、预热与测量目标之和再加 90 秒墙钟；不为获得通过而提高预算。

### 实际结果

CPU 以单核 100% 计，RSS 为采样峰值。

| 档位               |     实际测量时间 | 每 actor delta/s |    CPU |   RSS 峰值 | 结果                     |
| ------------------ | ---------------: | ---------------: | -----: | ---------: | ------------------------ |
| 12 actor           |        60.013 秒 |           19.996 | 15.23% | 488.26 MiB | 完成，功能与安全检查通过 |
| 64 actor           |        60.029 秒 |           19.990 | 44.59% | 568.05 MiB | 完成，功能与安全检查通过 |
| 64 actor 长跑      |       300.036 秒 |           19.998 | 56.16% | 628.23 MiB | 完成，384,000 个测量输入 |
| 256 actor 修正复测 | 124.917 秒后中止 |            6.556 | 94.80% | 635.93 MiB | 未完成，触及固定墙钟预算 |

所有档位均完成本测试创建资源的收尾：timer、listener、subscriber 归零，12 / 64 / 256 runtime 各自全部关闭。成功档位及 256 复测的在线恢复比较、活动节点保留与 256 节点截断检查有记录；256 因预算中止而未完成最终结算，不能写成全链路成功。

64 actor 五分钟运行中，heap 起点约 177 MiB、采样峰值约 405 MiB、结束约 281 MiB，后段采样斜率为负；数据不支持把短窗口上涨直接判为泄漏，也不能据一次五分钟观测宣称没有泄漏。内存中实际保留了 43,002 个 journal 事件，约 11.46 MB JSON，成本已包含在内。

### 原始失败与基准修正

第一次 256 actor 运行超预算后，旧基准只在完整结束时返回资源字段，导致部分测量丢失；过期批次也未让出事件循环，影响 driver timer。原记录仍在 JSON，`measuredWallMs=0` 明确标为缺失，不解释成耗时为零。

只修正了基准的部分结果保留和过期批次让出事件循环，**没有修改生产并发、重试、超时、节流或安全预算**。复测仍只能达到 6.556 delta/s/actor，124.917 秒只完成 209,664 个测量输入，未完成预定 307,200 个，真实失败保留。

当前证据说明：在包含投影/编码/测量开销的这条本机链路下，256 actor × 20 delta/s 超过已测能力。它不是 scheduler 死锁证据，也不能仅凭这一数据定位某个生产组件为瓶颈。

## 4. 浏览器渲染与负载交互

使用应用内浏览器真实渲染共享 WorkflowRunDigest / WorkflowTimeline / WorkflowRunPhaseList 和父 ConversationProjectionStore，不以 SSR 代替渲染。React Profiler 的 commit 计数、均值、最大值覆盖完整测量；p50/p95 只覆盖最多 2048 个最近样本。RAF 同样保留有界样本，首尾未观测段单独说明，不编造帧。

原始 12 actor 长跑样本已保留：测量约 888 秒，React commit 均值 9.504ms、最近 p95 28.800ms，详情可打开，停止后订阅及 timer 全部归零。原恢复校验报告一次失败，已通过实际 Controller + Store 复现为 schema 解析调整对象键顺序导致的 JSON 字符串比较误报；语义深比较相等。此样本不计为成功功能验收，规范化比较和负例回归完成后另记复测。

修正后实际完成如下四档，每档预热 10 秒、测量超过 60 秒。p95 均指最近有界样本；>50ms 比例覆盖整个测量期间的已观测 RAF 间隔。

| 场景                          | 测量时长 | 实际 delta/s/actor | React commit 均值 / 最近 p95 | RAF 最近 p95 | RAF >50ms |
| ----------------------------- | -------: | -----------------: | ---------------------------: | -----------: | --------: |
| 12 actor，1280px，continuous  |  77.365s |             19.983 |             9.044 / 25.900ms |     33.200ms |     1.78% |
| 64 actor，1280px，continuous  |  84.560s |             19.986 |             6.951 / 24.800ms |     41.600ms |     0.93% |
| 256 actor，1280px，continuous |  81.628s |             16.208 |            10.819 / 33.500ms |     87.600ms |    74.38% |
| 64 actor，390px，replayable   |  77.198s |             20.130 |             8.912 / 28.100ms |     37.500ms |     6.29% |

四档的页面错误及恢复不一致均为 0；每档在负载中实际操作了 Recover、Stale frame 和共享组件的真实详情按钮。停止后组件卸载，RAF、状态/输入/恢复 timer、error listener、transport listener、订阅全部归零。节点窗口最大 256、活动 actor 保留、截断提示均可见。390×844 的页面宽度与 scrollWidth 同为 390，没有页面级横向溢出；这是桌面浏览器的窄屏验证，不是真手机网络测试。

256 actor 虽通过功能一致性和清理检查，但浏览器测得 16.208 delta/s/actor，低于输入目标，已观测 RAF 间隔中 74.38% 超过 50ms，说明开发构建下出现明显流畅性问题。不能用这次浏览器功能通过覆盖运行时的超预算失败。64 actor 窄屏的瞬时补追使测量窗口均速略高于 20，不代表输入策略加速；不同场景也不应因 commit 数或均值非单调就宣称容量越高反而越快。

修正后的 RAF 间隔覆盖率均超过 99.8%，原始版本约 62.827 秒的首尾未覆盖段由于缺少端点记录无法进一步归因，未扣除墙钟或补造帧。基准新增 9 个回归覆盖双 profile 的实际恢复、字段值/缺失/数组顺序负例、stale、重复停止与计时冻结。所有 fixture 在正式复测期间 hash 冻结。
